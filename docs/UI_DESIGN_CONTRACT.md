# KYRO interface contract

Surface: authenticated engineering workspace. User: developer evaluating security evidence and approving a controlled patch. Primary action progresses from connecting a repository to scanning, reviewing a finding, approving a plan and independently verifying the result.

Hierarchy: expressive access screen with an original metallic K and orbital engineering diagram, a focused sign-in/setup form, then persistent grouped navigation, project context, one page heading, actionable data, provenance and limitations. All product screens share the refreshed typography, controls, panels and semantic states. The overview combines actual API counts with a four-link workflow guide; the guide is navigation, not fabricated progress. Empty installations show setup actions.

Palette: midnight #090d15, layered navy panels, warm pearl #f4f2ec headings, blue #89b4ff actions, emerald verification, warm amber partials and coral errors. Violet is a secondary engineering accent. Inter variable and JetBrains Mono fonts remain locally bundled under OFL. Use richer visual depth on access/overview and quieter data surfaces on investigation pages. At least 4.5:1 normal text contrast, visible focus rings, 44 px touch controls and reduced-motion support.

Viewports: 390x844, 768x1024, 1440x900. At <=960 px sidebar becomes a keyboard-accessible drawer. Tables scroll within their region; headings and filenames wrap. No horizontal page overflow.

Reference observations: the user's internship-portal screenshot motivates differentiated accents, softer controls and clear filter groups. The user-supplied NovaStark website was inspected in a separate browser context: warm metallic typography and an orbital composition create a memorable entrance. KYRO uses an independently authored orbital K rather than copied branding, assets or a launch intro. GitHub's review workflow still motivates separate delivery approval, and scanner provenance stays visible. No private screenshot, code or credential is uploaded.

States: loading preserves heading and announces status; empty explains missing data and links to setup; error displays actual API failure with retry; partial distinguishes scanner failures and missing evidence; success confirms actual API operation; permission explains authentication, approval or unavailable integration and a safe next action. Browser evidence must substantiate these states.

Detector review: retain the self-hosted Inter face for dense engineering content and the two-pixel `.kyro-symbol` wordmark divider. These are intentional reviewed choices, with narrow rule/value exceptions for `frontend/src/styles.css` in `.impeccable/config.json`. No broad rule/file suppression was added. Evidence: `docs/evidence/design-hook-triage.json`.
